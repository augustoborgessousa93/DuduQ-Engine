# duduq-design-to-code-bridge

Use the DUDUQ registries before creating a primitive. Reuse first, extend second, create only with justification. Preserve learning clarity, accessibility, performance, responsive behavior and existing mechanics.

## Component geometry rule

When an official Penpot Main Component exists, a mechanic must map its instance to
the registered Core code component and must not define that component's internal
width, height, padding, radius, control size, mascot size, or visual material.
Geometry changes require a named, measured Design System variant first. Record the
Penpot Main ID, the Core module, and the permitted instance-level properties in the
component contract before implementation.

For cross-domain work, consult the premium-game-orchestrator routing reference.
